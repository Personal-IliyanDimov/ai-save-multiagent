# Glossary (short, paraphrased)

| Term | Meaning |
|---|---|
| ART (Agile Release Train) | Long-lived team of Agile teams that plans, delivers and often runs a solution together |
| Architectural Runway | Existing technical foundation that lets near-term features be built without major redesign |
| Benefit hypothesis | The measurable benefit you expect an epic/feature/story to produce |
| Business Owners | Stakeholders accountable for the ART's ROI, governance and compliance |
| Capability | Large-solution functionality spanning several ARTs, sized to fit a PI |
| Capacity allocation | Planned split of capacity by work type for a planning period |
| CDP | Continuous Delivery Pipeline: continuous exploration → integration → deployment → release on demand |
| Confidence vote | Fist-of-five vote on the team's/ART's belief they can meet PI objectives |
| Cost of Delay | Value lost by delaying a job; numerator of WSJF |
| Definition of Done | Agreed completeness criteria for an increment |
| Enabler | Backlog item that builds runway or improves the value stream |
| Epic | Significant initiative needing a Lean Business Case and portfolio approval |
| Feature | Functionality an ART can deliver within one PI |
| I&A (Inspect & Adapt) | End-of-PI event: demo, metrics, problem-solving workshop |
| IP Iteration | Innovation & Planning iteration — buffer, innovation, PI Planning, I&A |
| Iteration | Fixed timebox (usually 2 weeks) |
| LACE | Lean-Agile Center of Excellence — small team driving the transformation |
| Lean Business Case | Lightweight case describing an epic, its MVP, cost and expected value |
| LPM | Lean Portfolio Management: strategy & funding, portfolio operations, Lean governance |
| MVP | Smallest version that tests the epic hypothesis |
| NFR | Nonfunctional requirement — system quality acting as a constraint |
| PI (Planning Interval) | Cadence timebox (typically 8–12 weeks) |
| PI Objectives | Business/technical goals for a PI; committed or uncommitted |
| PI Planning | Cadence event aligning the whole ART on a plan for the next PI |
| ROAM | Risk handling: Resolved, Owned, Accepted, Mitigated |
| RTE | Release Train Engineer — ART servant leader and facilitator |
| Solution Intent | Repository of current and intended solution behavior and design |
| Solution Train | Construct coordinating multiple ARTs and suppliers for a large solution |
| Spike | Exploration enabler story to reduce uncertainty |
| STE | Solution Train Engineer — Solution Train servant leader and facilitator |
| Story | Small user-centric piece of functionality fitting in an iteration |
| Strategic themes | Portfolio business objectives that guide decisions |
| System Demo | Integrated demo of the whole ART's increment each iteration |
| Value stream | Sequence of steps delivering value to a customer (development or operational) |
| VMO | Value Management Office — facilitates LPM and Lean governance |
| WSJF | Weighted Shortest Job First = Cost of Delay ÷ Job Duration |
